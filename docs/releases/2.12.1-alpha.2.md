# MCP Firebird 2.12.1-alpha.2

October 15, 2026. Includes PR #46 for issue #45 and the previous `2.12.1-alpha.1` fixes.

## Full column descriptions

`describe-table`, `describe-batch-tables` and `get-field-descriptions` read the full `RDB$DESCRIPTION` BLOB. The former `CAST(... AS VARCHAR(500))` could fail the entire table description when one comment exceeded 500 characters. No truncation is introduced in JavaScript. Existing table authorization, transaction-safe BLOB resolution, query deadlines, masking and configured response-size limits remain in effect.

## Execution-plan status

When no plan can be retrieved, `get-execution-plan` now returns `success: false`, `plan: ""`, `planDetails: []` and `error: "Execution plan not available"`. The MCP envelope sets `isError: true` and retains the manual-tool guidance in `analysis`. Clients must handle this as an unavailable capability instead of accepting the old placeholder as a plan.

This change does not retrieve real plans through Firebird monitoring tables or execute the submitted SQL. SQL validation and permissions remain enforced. Use an authorized Firebird client such as `isql` with `SET PLANONLY ON` for manual plan inspection.

## Registered tool counts

`get-server-info` now reports names/counts from the actual registered catalog, including simple and event tools. `system-health-check.tools.total` uses that same count; the optional additive `tools.other` field covers categories outside database/metadata. Event tools are counted only when registration is permitted by the configured policy. Counts are not hardcoded.

The missing-index heuristic still does not inspect existing primary-key/index metadata, so its suggestions must be checked against existing indexes. This release does not claim to fix that separate observation from #45.

## Install

```sh
npm install -g mcp-firebird@2.12.1-alpha.2
```

For an existing `npx` MCP launcher, select `mcp-firebird@2.12.1-alpha.2` (or `mcp-firebird@alpha`) in its arguments. Keep the existing transport, connection and security settings and restart the MCP process. No new configuration flag is required. Stable `latest` remains 2.12.0.

## Validation scope

The local live smoke on Firebird 2.5.9 reproduced the old 500-character cast failure and verified intact 514-character and 10,000-character Unicode descriptions across all three metadata paths, including a NULL first description. It also checked both the query function and MCP tool's unavailable-plan error and used a sequence to verify that the submitted SELECT was not executed. Previous SQL-policy, BLOB, statistics, write, audit and event regressions also passed. The UUID-named disposable database and audit file were removed afterwards.

Automated regressions cover policy/size-limit denials, mocked pure/native driver labels, tool contracts and SDK 1/SDK 2 STDIO/HTTP status/catalog consistency. Live validation against the reporter's Firebird 5.0.3 and native-driver/charset-specific environments is still requested; the local 2.5.9 run does not establish that coverage.
