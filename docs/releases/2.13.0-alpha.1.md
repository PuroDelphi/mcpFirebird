# MCP Firebird 2.13.0-alpha.1

> These improvements are now included in stable [2.12.3](2.12.3.md), continuing the 2.12 stable line. No alpha installation is required. The historical notes below describe this alpha as originally released.

This alpha completes the pending optimizer-plan and duplicate-index observations from #45. It includes stable 2.12.2 and does not change `latest`.

## Improvements

- Obtain real legacy optimizer plans using feature-detected prepare/info APIs, without executing the submitted SELECT, binding parameter values or reading other sessions' monitoring data. Statement cleanup and read-only transaction rollback are awaited; unavailable plans remain honest errors.
- Check existing catalog indexes before generating single-table suggestions, including primary-key/unique indexes and composite left prefixes. Distinguish ordering direction, warn about inactive equivalents instead of proposing duplicates, and do not assume partial/expression indexes provide general coverage.
- Preserve SQL/table/role policies, row filters, masking projection restrictions, audit requirements, quotas, deadlines and response limits. Never execute index DDL. Keep historical ISO/UTC dates by default; wall-clock dates remain opt-in.
- Cover node-firebird lazy-send allocation/preparation and deferred DROP acknowledgments so the connection is not recycled with pending work.

## Try it

```sh
npm install -g mcp-firebird@2.13.0-alpha.1
```

Or use `mcp-firebird@alpha` in your existing launcher. Retain existing connection/security settings and restart the MCP. No new flag is required. Read the [English guide](../query-diagnostics.md) or [resumen en español](../query-diagnostics.md#español) for examples and limitations. Only SELECT-first statements are supported for plans; index advice is a conservative heuristic, not an automatic optimizer or performance guarantee.

## Validation

Local release validation passed typecheck, build, lint error checks, **1,348 unit tests**, **116 protocol/Node tests without skips**, and compiled security-runtime checks. Protocol tests include STDIO/HTTP with both SDK generations. Diagnostics were also exercised from the extracted npm artifact (64 files); the production dependency audit reports zero known vulnerabilities. Real integration uses a disposable Firebird 2.5.9 database and the pure-JS driver: plans are retrieved while an incrementing sequence remains unchanged; primary-key/composite/descending/inactive indexes are checked without creating suggested indexes. Existing BLOB/date/policy/audit/event smoke checks are retained.

Native API paths are covered with controlled adapters, not a live native addon. Firebird 5 is not available in this test environment. Validate the alpha in your own deployment before production promotion. No dependencies/drivers were upgraded, GitHub Actions remains disabled, and stable 2.12.2 is unchanged.
